# Requirement Analysis
1. Inspect existing code, documents, forms, spreadsheets, and numbering practices.
2. Separate confirmed facts, assumptions, and questions.
3. Identify user roles only after confirming actual responsibilities and permissions.
4. Map create, validate, allocate, issue, search, amend, cancel, and audit workflows as applicable.
5. Define functional and non-functional requirements: security, availability, performance, accessibility, backup, auditability, maintainability.
6. Explicitly record numbering scope, year basis, reset rule, prefixes, padding, cancelled numbers, and concurrency behavior.
7. Write testable Given/When/Then acceptance criteria.
8. Flag legal, retention, and official policy questions; do not invent answers.

## Output
Current state; actors/permissions; workflows; functional and non-functional requirements; confirmed rules/assumptions/open questions; acceptance criteria.
