## What to build

แนวทางล่าสุด 16 พฤศจิกายน 2026: ใช้ CENTRAL ตรวจบัญชีโดยตรงผ่าน backend แบบอ่านอย่างเดียวเมื่อใช้งานจริง ไม่ต้อง dump CENTRAL หรือคัดลอก PASSWORD เข้าฐานใหม่ การตรวจ mapping ใช้ข้อมูลจำเป็นจาก CENTRAL เมื่อช่องทางพร้อม ดู [ADR 0003](../adr/0003-live-central-and-genbook-cutover.md) ช่องทางเชื่อมยังต้องได้รับอนุญาตตามเงื่อนไขเดิม

ผู้ใช้ยืนยัน 12 พฤศจิกายน 2026 ให้พัฒนา UI/ล็อกอินด้วยบัญชีจำลองใน localhost ต่อได้ และแยกการเชื่อมบัญชีคณะจริงเป็นงานที่ต้องผ่านก่อนเปิดใช้งาน งานนี้รวบรวมหลักฐาน AC1 ที่ยังไม่ผ่านของ T02 และตรวจการสลับจากตัวเชื่อมทดสอบไปช่องทางบัญชีที่คณะอนุญาตจริง โดยยึดพฤติกรรมเดิม ไม่เพิ่ม SSO เอง

งานนี้ไม่บล็อกการเริ่ม T04 รุ่น local แต่ห้ามเปิดให้บุคลากรใช้งานจริงก่อนตรวจรับครบ บัญชีสังเคราะห์/ผล local compatibility ไม่ใช่หลักฐานว่าบัญชีคณะเชื่อมได้

## Acceptance criteria

- [ ] มีเอกสารรับรองหรือผลทดสอบที่ได้รับอนุญาตสำหรับช่องทางบัญชีคณะที่ใช้จริง endpoint/transport และความหมายของผลยืนยันตัวตน โดยไม่สร้างฐานรหัสผ่านคณะขึ้นเอง
- [ ] ยืนยันรหัสบุคลากร/หน่วยงานที่เชื่อถือได้และการจับคู่ประวัติเดิม รวมความคงที่/การเปลี่ยนรหัส ไม่ใช้ชื่อแสดงผลหรือ email แทนคีย์เจ้าของโดยสมมติ
- [ ] ตรวจบัญชีถูกต้อง ผิด ระงับ/พ้นสภาพ ขาด ID/หน่วยงาน และบริการขัดข้อง รวมกฎถอนสิทธิ์/ย้ายหน่วยงานตาม T02 และระยะเวลารับรู้สถานะที่เจ้าของรับรอง
- [ ] ใช้ session ที่ server เพิกถอนได้ ตรวจ expiry/logout/replay cookie เดิมและสิทธิ์ทุก protected operation ไม่มี fallback เมื่อยืนยันตัวตนไม่ได้
- [ ] ตรวจ production build/config ไม่รวม test login, fixture credential, test adapter หรือ endpoint ทดสอบ แยก secrets ฝั่ง server และไม่มีทางเปิด mock จาก header/query/cookie
- [ ] บันทึกหลักฐานทดสอบแบบไม่เปิดเผยข้อมูลส่วนบุคคล/รหัสผ่าน ผ่าน QA และเจ้าของระบบตรวจรับก่อนเปิดใช้ ส่งหลักฐานกลับ T02 AC1; การตรวจรับนี้ไม่ใช่การอนุมัติ deploy หรือย้ายข้อมูลจริง

## ขอบเขตและหลักฐาน

- 18 พฤศจิกายน 2026: ผู้ใช้ให้ใช้ Core CENTRAL ของ ronaldo-service และอนุมัติเพิ่ม HTTP API กลางแล้ว genbook-no จัดการ session ของตัวเองผ่านตัวเชื่อม server-only; ทดสอบ HTTP ระหว่างสองโปรเจกต์ด้วย FakeDirectory ผ่าน ครอบคลุม login/session rotation/logout/replay และ protected API ดู [รายละเอียด](../specs/ronaldo-auth.md) ยังไม่ใช่ผลทดสอบบัญชีคณะจริง จึงยังไม่ติ๊ก AC/ปิดงานหรืออนุมัติ deploy

- [T02](./02-identity-permissions.md) คงสถานะ 4/5 จน AC1 มีหลักฐานจริง ไม่ติ๊กว่าเสร็จเพียงเพราะย้ายการติดตามมางานนี้
- [T04](./Done-04-sign-in.md) ทำรุ่น local ได้ตามคำยืนยันล่าสุด แต่ผลสำเร็จเฉพาะบัญชีจำลองไม่รับรอง production readiness
- [รายงานระบบเดิม](../specs/legacy-identity-permissions-analysis.md) และ [sandbox](../../tools/legacy-sandbox/README.md) เป็นฐานออกแบบ ไม่ใช่บริการ identity production
- ไม่ทดสอบบัญชีจริงหรือเชื่อม `central` ภายนอกโดยไม่มีขอบเขตที่ได้รับอนุญาต ไม่เก็บรหัสผ่าน/token/cookie ใน source, issue หรือผลทดสอบ
- ก่อนวันเปิดใช้ต้องผ่าน T13 และเงื่อนไขเปิดใช้งาน/ย้ายข้อมูลของ ticket อื่นที่เกี่ยวข้อง ไม่ตีความป้ายพร้อมเริ่มเป็นอนุมัติเปิด production

## บันทึกความคืบหน้า

- 12 พฤศจิกายน 2026: แยกงานก่อนเปิดใช้ตามคำยืนยันผู้ใช้ ยังไม่มีผลทดสอบบัญชีคณะจริง เกณฑ์ 0/6
- QA แผนผ่าน ไม่พบ Critical/High/Medium; ลิงก์และยอด 13 tickets ตรวจผ่าน ไม่มี dependency cycle รอบนี้แก้เอกสาร/issue tracker เท่านั้น ใช้ผล lint/typecheck รอบก่อน ไม่รัน runtime tests ซ้ำ และไม่อ้างว่าเริ่ม implementation T04 แล้ว

- 12 พฤศจิกายน 2026: T04 รุ่น local ผ่าน 6/6 และ QA แล้ว dependency ด้าน login พร้อม; T13 ยังคงเป็นเงื่อนไขก่อนเปิดใช้จริง

- 16 พฤศจิกายน 2026: ผู้ใช้ระบุฐานบัญชีจริงและอนุญาตอ่านฐานเดิมเท่านั้น TCP เข้าถึงได้ แต่ MySQL ไม่รองรับ TLS; การอ่านแบบไม่เข้ารหัสถูก automatic approval review ปฏิเสธ รอช่องทางเข้ารหัสหรือคำอนุญาตความเสี่ยงเพิ่มเติม ยังไม่มี schema query/login/import จริงและคง 0/6 ดู [ผลตรวจ](../specs/remote-readonly-discovery.md)
