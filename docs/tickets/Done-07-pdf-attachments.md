**เหตุผลคะแนน:** ต้องตรวจไฟล์ ป้องกันดาวน์โหลด และกู้คืนความล้มเหลวระหว่างไฟล์กับฐานข้อมูล

**เงื่อนไขเพิ่มเติม:** ตาม T03 รับเฉพาะ PDF ขนาดจริง ≤2,097,152 bytes (2 MiB รวมขอบ), ตรวจ MIME และอ่านโครงสร้างฝั่ง server ปฏิเสธไฟล์เสีย/เข้ารหัส; ไฟล์ใหม่ไม่ผ่านให้คงไฟล์เดิม หนังสือไม่ลับปกติ/ย้อนหลังออกเลขก่อนแนบ ภายหลังถ้ามีค้างไฟล์ของผู้ทำรายการให้บล็อกคำขอเลขถัดไป ลับทั้งสองแบบยกเว้นไฟล์ แต่ไฟล์ที่แนบยังต้องผ่าน validation/authorization

## What to build

เจ้าของแนบ PDF ให้หนังสือ เห็นความครบถ้วน และผู้มีสิทธิ์ดาวน์โหลดได้โดยไม่เปิดไฟล์ให้บุคคลอื่น

## Acceptance criteria

- [x] ตรวจชนิดเนื้อหา/ขนาดบน server ตามกติกา ไม่เชื่อเฉพาะนามสกุลหรือชนิดที่ client ส่ง
- [x] สถานะครบถ้วนและข้อยกเว้นหนังสือลับ/ย้อนหลังตรงตามกติกาที่ยืนยัน
- [x] ไฟล์จัดเก็บแบบป้องกันการเข้าถึงโดยตรง และ authorize ทุกการดาวน์โหลด
- [x] จัดการไฟล์/ฐานข้อมูลล้มเหลวโดยไม่แสดงว่ามีไฟล์สำเร็จทั้งที่ไม่มี พร้อม audit ที่เกี่ยวข้อง
- [x] มี browser/HTTP tests สำหรับอัปโหลด/ดาวน์โหลด ไฟล์ผิดชนิด เกินขนาด ข้ามสิทธิ์ และการกู้คืนล้มเหลว
- [x] หน้าจอเข้าถึงได้ มี validation/loading/error; lint, typecheck, เทสต์ผ่านและ QA ตรวจ

## บันทึกความคืบหน้า

- 12 พฤศจิกายน 2026: T03 รับรอง PDF ทั้งขนาด/การตรวจ/เวลาแนบ/ไฟล์ค้างครบแล้ว ใช้ X08/X09/X11–X15/X17; เปลี่ยนลับเป็นไม่ลับโดยไม่มี PDF ได้และเป็นค้างไฟล์ ไม่เปลี่ยนสิทธิ์อ่านตาม T02 เกณฑ์ T07 ยังไม่ผ่านเพราะเป็นงาน implementation ที่ยังไม่ทดสอบ

- 11 พฤศจิกายน 2026: สร้างไฟล์ติดตามจาก GitHub; ยังไม่มีหลักฐานปิดงานหรือเกณฑ์รับงานที่ผ่าน
- ผลตรวจ/หลักฐาน: [T07 รุ่น local](../specs/local-pdf-attachments.md)
- อุปสรรคปัจจุบัน: ไม่มี blocker รุ่น local; legacy PDF inventory อยู่ T12 และการเปิดจริงยังรอ T12/T13

- 13 พฤศจิกายน 2026: พัฒนาแนบ/เปลี่ยน PDF ของเจ้าของ ดาวน์โหลดตาม T02 ตรวจเนื้อหา/ขนาด/เข้ารหัส เก็บ private immutable blob และ transaction/version/audit ก่อน–หลัง; T07 browser/HTTP ผ่าน 8/8 และ QA ไม่พบ Critical/High/Medium ค้าง GitHub #8 ยัง OPEN (ไม่ได้อัปเดตภายนอก)
