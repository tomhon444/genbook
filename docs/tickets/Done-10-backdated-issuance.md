## What to build

บุคลากรที่มีสิทธิ์เลือกวันที่ย้อนหลัง รับเลขแทรกตามกติกา และเปิดรายการพร้อมข้อมูลย้อนหลังที่ถูกต้อง

## Acceptance criteria

- [x] ใช้วิธีเลือกเลขหลัก/ลำดับย่อยและขอบเขตข้ามปีที่เจ้าของระบบยืนยัน ไม่คาดเดาจากตัวอย่าง 004.1
- [x] บังคับสิทธิ์ วันเวลา วันหยุด และขั้นตอนอนุมัติตามกติกา
- [x] จัดสรรย้อนหลังด้วย transaction/unique constraints และเก็บ audit โดยแยกวันที่หนังสือจากเวลาออกจริง
- [x] มี browser tests เลือกวันที่ รับเลข และเปิดรายละเอียด พร้อม validation/error
- [x] HTTP tests ยืนยันการแทรกพร้อมกันไม่ซ้ำ การส่งซ้ำ rollback และข้ามปีตามผลลัพธ์ที่อนุมัติ
- [x] ก่อนเริ่มตรวจผลกติกา PDF จากข้อ 03: หากเส้นทางย้อนหลังต้องแนบ PDF จึงจะครบเงื่อนไข ให้เพิ่ม native blocker ไปยังงาน 07 และรอให้เสร็จก่อนเริ่ม/ตรวจรับงานนี้; หากไม่ต้องใช้ไฟล์ งานนี้ไม่รอ 07 ห้ามอ้างว่าเสร็จทั้งที่เงื่อนไขบังคับยังไม่พร้อม
- [x] lint, typecheck, เทสต์เกี่ยวข้องผ่านและ QA ตรวจ

## บันทึกความคืบหน้า

- 12 พฤศจิกายน 2026 รอบสาม: รับรอง PDF ไม่ลับและกฎไฟล์ค้างแล้ว เพิ่ม T07 เป็น dependency ตามเกณฑ์เดิม ใช้ขนาด/validation ของ T07 และ X08–X17 ของ T03; ข้อความที่ยังรอ PDF ในบันทึกรอบก่อนด้านล่างเป็นประวัติ ไม่ใช่สถานะปัจจุบัน

- 12 พฤศจิกายน 2026 รอบสอง: รับรองวิธีเลือกต้นทางที่อ่านได้และมีสิทธิ์ใช้ชุด คงชุด/ปี/วันที่/เลขหลัก เพิ่มเลขย่อยจำนวนเต็มพร้อมกันไม่ซ้ำ ทุกปีที่มีต้นทางย้อนหลังที่อ่านได้ ไม่มีต้นทางวันที่ต้องการปฏิเสธ ไม่เติมช่องว่าง; retry/rollback ใช้ X05/X06 ของ T03 กติกาเลขครบระดับออกแบบแล้ว แต่เกณฑ์ T10 ยังไม่ผ่านเพราะยังไม่พัฒนาหรือทดสอบ PDF ไม่ลับยังรอคำตอบก่อนตัดสิน blocker T07

- 12 พฤศจิกายน 2026: T03 รับรองผู้มีสิทธิ์ใช้ชุดเลขขอย้อนหลังได้ทันที และหนังสือลับย้อนหลังยกเว้น PDF แล้ว ยังรออัลกอริทึม/ช่วงย้อนหลัง/ข้ามปีและ PDF ของไม่ลับ จึงยังไม่เพิ่ม blocker T07 หรืออ้างว่า T10 เริ่มพัฒนา/ผ่านเกณฑ์แล้ว
