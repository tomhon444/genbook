## ข้อสรุปสุดท้าย — คำยืนยันรอบสาม 12 พฤศจิกายน 2026

ผู้ใช้ตอบ “ยืนยันตามนี้” เรื่องฟิลด์/การแก้ชนกัน, “ใช้ 2 MiB และกฎตรวจตามนี้” เรื่อง PDF, “ยืนยันตามนี้” เรื่องไฟล์ค้าง และย้ำ “ยืนยันตามนั้น” ข้อสรุปรอบนี้แทนข้อความรอยืนยัน E5/E6 และ X07–X09 ในประวัติเดิม

- เฉพาะเจ้าของแก้เรื่อง ผู้รับ หน่วยงานรับเรื่อง ผู้ลงนาม ความลับ การเผยแพร่ และ PDF ได้ ห้ามแก้เจ้าของ ชุดเลข ปี เลขหลัก/ย่อย วันที่หนังสือ และเวลาออกจริง ใช้ version ตรวจแก้ชนกัน: รายการที่บันทึกทีหลังจาก version เก่าต้องโหลดใหม่ ไม่เขียนทับเงียบ ๆ การแก้และ audit ก่อน/หลังมีผล atomic
- รับ PDF ที่มีขนาดจริงไม่เกิน **2,097,152 bytes (2 MiB)** รวมขนาดเท่าขอบ ไม่ใช้ 2,000,000 bytes ตรวจ MIME และอ่านโครงสร้าง PDF ฝั่ง server ไม่เชื่อเฉพาะ extension/Content-Type จาก client ปฏิเสธไฟล์เสียและไฟล์เข้ารหัส ถ้าไฟล์ใหม่ไม่ผ่านต้องคงไฟล์เดิม
- หนังสือไม่ลับทั้งปกติและย้อนหลังออกเลขก่อนแล้วแนบ PDF ภายหลัง หากผู้ทำรายการยังมีหนังสือไม่ลับค้างไฟล์ให้บล็อกขอเลขถัดไปทั้งสองเส้นทาง จนไม่เหลือรายการค้าง ตรวจฝั่ง server ก่อนจัดสรรโดยไม่ออกเลข/เพิ่ม counter เมื่อถูกบล็อก ไม่เพิ่มสิทธิ์อ่านรายการของผู้อื่น
- เมื่อเจ้าของเปลี่ยนหนังสือลับที่ไม่มี PDF เป็นไม่ลับ ให้บันทึกเป็นรายการค้างไฟล์และใช้กฎบล็อกขอเลขถัดไป ไม่คืนเลขหรือบังคับออกหนังสือใหม่ หนังสือลับทั้งสองแบบยกเว้นไฟล์ หากมี PDF ยังต้องตรวจชนิด/ขนาดและสิทธิ์ T02
- T10 ต้องรอ T07 เพื่อให้เส้นทางย้อนหลังไม่ลับแนบไฟล์ได้ครบ ส่วน T05 ทำการออกเลขและสถานะค้างไฟล์ได้ก่อน T07 ตามลำดับเดิม ไม่เพิ่ม dependency ที่ทำให้ T05→T06→T07 วนกลับ
- รายละเอียดเครื่องมืออ่าน PDF, schema/version column และ transaction/การกู้คืนไฟล์เป็นการออกแบบ implementation ใน T05/T07/T09/T10 ต้องรักษาผลลัพธ์ที่รับรอง ไม่ใช่กติกาธุรกิจที่ยังรอคำตอบใน T03

## ฐานกติกาที่รับรองแล้ว

- [T01](./Done-01-numbering-rules.md): ชุดเลข `bookdept` + ปี, prefix เดิม, ลำดับขั้นต่ำ 4 หลัก; ปีปฏิทิน พ.ศ. และคำสั่ง `00006` อิงปีวันที่หนังสือ ตรวจสิทธิ์/เวลาขณะจัดสรรตาม Asia/Bangkok ทั่วไปทุกวัน 07:00:00–22:30:59 การเงิน/พัสดุรหัส 204 ตลอดเวลา ไม่ใช้วันหยุดห้ามออกเลข
- [T02](./02-identity-permissions.md): เฉพาะเจ้าของแก้ข้อมูล/ไฟล์/ความลับ/เผยแพร่ และอ่าน audit ของตน ผู้ดูแลหรือผู้จัดการชุดเลขไม่ได้สิทธิ์อ่านหนังสือลับหรือแก้แทนอัตโนมัติ สิทธิ์ย้อนหลังและขอบเขตยกเลิกยืนยันเพิ่มเติมในรอบแรกด้านล่าง
- การจัดสรรต้อง concurrency-safe และมี unique constraint; เก็บประวัติ ไม่ใช้เลขยกเลิก/ผิดพลาดกลับเงียบ ๆ รายละเอียด retry และช่องว่างรับรองตามรอบสองด้านล่างแล้ว

## คำยืนยันรอบแรก — 12 พฤศจิกายน 2026

หลักฐาน: ผู้ใช้ตอบคำถามในบทสนทนาโดยตรงทั้งสามข้อ ข้อสรุปนี้มีผลเหนือข้อความรอยืนยันก่อนหน้าเฉพาะเรื่องเดียวกัน

- “ผู้มีสิทธิ์ใช้ชุดเลขนั้น ขอได้ทันที”: รับรองสิทธิ์ย้อนหลังโดยไม่รออนุมัติ ไม่เพิ่มสิทธิ์อ่านต้นทางของผู้อื่น อัลกอริทึมแทรก ช่วงย้อนหลังและข้ามปียังรอยืนยัน จึงยังไม่ผ่าน AC1
- “ยังไม่มีในรุ่นแรก”: ไม่พัฒนาการยกเลิกในรุ่นแรก T11 เป็นไม่ดำเนินการ ไม่ใช่งานพัฒนาเสร็จ AC2 ผ่าน ไม่ถือว่าอนุญาตให้ลบ/คืนเลขหรือเปลี่ยนประวัติยกเลิกที่ย้ายมาจากระบบเดิม
- “ยกเว้น PDF สำหรับหนังสือลับทั้งสองแบบ”: หนังสือลับปกติและย้อนหลังไม่ต้องแนบ PDF หากมีไฟล์ยังบังคับสิทธิ์อ่านตาม T02 ส่วนชนิด/ขนาด/ตรวจไฟล์และจังหวะแนบของหนังสือไม่ลับยังรอยืนยัน จึงยังไม่ผ่าน AC5

## คำยืนยันรอบสอง — 12 พฤศจิกายน 2026

หลักฐาน: ผู้ใช้ตอบ “ใช้ตามนี้” ต่อวิธีแทรกและ retry และเลือก “ทุกปีที่มีต้นทางที่อ่านได้ คงปี/วันที่ต้นทาง” ข้อสรุปนี้แทนสถานะรอยืนยันเรื่องเดียวกันในรอบแรก

- ผู้ใช้เลือกรายการต้นทางที่ตนอ่านได้และมีสิทธิ์ใช้ชุดเลข คงชุด/ปี/วันที่/เลขหลักเดิม เพิ่มลำดับย่อยจำนวนเต็ม .1, .2, … .10 ไม่เปลี่ยนเลขหลักและไม่เติมเลขขาดช่วง วันที่ต้องการไม่มีต้นทางให้ปฏิเสธการแทรก
- อนุญาตทุกปีที่มีต้นทางที่อ่านได้ ไม่จำกัดเฉพาะปีปัจจุบัน ตรวจสิทธิ์ชุดและเวลาจัดสรรตาม T01 เสมอ แยกวันที่หนังสือย้อนหลังจากเวลาออกจริง ห้ามใช้ต้นทางอนาคตเป็นการขอย้อนหลัง
- ขอแทรกพร้อมกันต้องได้คนละเลขย่อยในชุด+ปี+เลขหลักเดียวกัน ไม่กำหนดลำดับว่าใครได้ก่อน เช่น ต้นทาง 0042 ยังไม่มีเลขย่อย → .1 กับ .2; ตัวนับเลขหลักไม่เปลี่ยน หากเลขหลักสูงสุด 0042 และไม่มีคำขอปกติอื่น เลขปกติถัดไปคือ 0043
- ตัวอย่างข้ามปี: ปัจจุบันปี 2570 เลือกต้นทางชุด S ปี 2569 วันที่ D เลข 0042 ที่มี .1 แล้ว → ได้ 0042.2 ปี 2569 วันที่ D; ไม่เปลี่ยน counter ปี 2570 หากไม่มีต้นทางวันที่ต้องการต้องปฏิเสธ ไม่เติมเลขว่าง
- คำขอเดิมส่งซ้ำคืนรายการเดิมหลังตรวจสิทธิ์; รหัสเดิมแต่ข้อมูลต่างปฏิเสธ ล้มเหลวก่อนบันทึกสำเร็จ rollback หนังสือ/ตัวนับ/audit ทั้งชุด ไม่ถือว่าเคยออกเลขแล้ว บันทึกสำเร็จแต่ตอบกลับหาย retry คืนรายการ/เลขเดิม ไม่จัดสรรเพิ่ม
- แนบไฟล์ล้มเหลวหลังออกเลขสำเร็จให้แนบใหม่ที่รายการเดิม ไม่คืนเลข ไม่เติมเลขขาดช่วงอัตโนมัติ ไม่ใช้เลขยกเลิกเดิมกลับเงียบ ๆ รายละเอียดขอบเขต/อายุรหัสคำขอต้องออกแบบโดยคงผลลัพธ์ที่รับรองนี้

## ประเด็นตัดสินใจ — ยืนยันครบตามสามรอบ
