## What to build

บุคลากรกรอกข้อมูลจำเป็นสำหรับหนังสือวันที่ปัจจุบัน ดำเนินขั้นตอนอนุมัติหากกติกากำหนด รับเลข และเปิดรายการที่บันทึกสำเร็จได้ครบเส้นทาง

## Acceptance criteria

- [x] ใช้ประเภท/ชุดเลข/ปี/prefix และข้อมูลขั้นต่ำที่ยืนยัน; จำกัดให้เจ้าของเห็นก่อนขยายการเผยแพร่
- [x] ตรวจสิทธิ์ input วันเวลา/วันหยุด และขั้นตอนอนุมัติที่ยืนยันบน server
- [x] บันทึกเลข หนังสือ และ audit แบบ atomic ด้วย MySQL transaction และ unique constraints; ไม่ใช้ MAX+1 เพียงอย่างเดียว
- [x] แสดงเลขที่สำเร็จ เปิดรายละเอียดและรายการล่าสุดได้ พร้อม loading/error และการเข้าถึงมือถือ/คีย์บอร์ด
- [x] HTTP tests ใช้ MySQL ทดสอบจริงพิสูจน์เลขไม่ซ้ำเมื่อขอพร้อมกัน คำขอซ้ำ และ rollback ตามกติกาที่ยืนยัน
- [x] browser tests ครอบคลุมสำเร็จ/ปฏิเสธและอ่านผล; เพิ่มเครื่องมือทดสอบขั้นต่ำใน slice นี้หรือข้อ 04 ตามความจำเป็น
- [x] lint, typecheck, เทสต์เกี่ยวข้องผ่านและ QA ตรวจ โดยไม่ใช้ข้อมูล production

- 12 พฤศจิกายน 2026: พัฒนารุ่น local ครบเส้นทางและ QA อิสระผ่าน 7/7 ดู [คู่มือ/ขอบเขต](../specs/local-normal-issuance.md) ใช้ MySQL 8 แยกใหม่ ไม่อ่าน/เขียนฐานเก่าหรือ production
- หลักฐาน: lint/typecheck/build ผ่าน; auth provider 9/9; กติกา MySQL 7/7; HTTP/browser T05 9/9 และ regression โหลดรายการล้มเหลว 1/1; T04 regression 6/6; production isolation 3/3 รวม endpoint ออกเลข
- พิสูจน์คำขอพร้อมกัน 16 รายการไม่ซ้ำ; ส่งรหัสเดิมพร้อมกัน 8 ครั้งได้เพียงรายการเดียว; trigger audit ล้มเหลว rollback ทั้งหนังสือ/counter/audit และ retry เริ่ม 0001; ทดสอบค้างไฟล์ข้ามชุด/ไม่ใช่รายการล่าสุด, เวลาหลังรอล็อก, ปีใหม่, 9999→10000, ปลายทางภายใน, owner-only และตอบกลับหายแล้ว reload/retry
