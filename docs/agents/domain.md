# Domain Docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the work.

If these files do not exist, proceed silently.
Create them lazily when domain terms or decisions are resolved.

## Vocabulary

Use the terms defined in the glossary consistently.
Identify missing concepts for domain modeling rather than
inventing business rules.

## Decision conflicts

Explicitly flag any proposal that contradicts an existing ADR.
Reference the affected ADR and explain the proposed change.
