# สเปกออกแบบระบบออกเลขหนังสือราชการ — รุ่นแรก

สถานะ: ยืนยันขอบเขตการทดสอบแล้วเมื่อ 11 พฤศจิกายน 2026; กติกาธุรกิจที่ยังเปิดอยู่ระบุใน Further Notes

## Problem Statement

บุคลากรภายในคณะวิศวกรรมศาสตร์ มหาวิทยาลัยสงขลานครินทร์ ต้องการระบบใหม่ทดแทนระบบออกเลขหนังสือเดิม เพื่อขอเลข บันทึกรายละเอียด จัดการเอกสาร และค้นหาประวัติได้สะดวก โดยเลขต้องไม่ซ้ำและข้อมูลต้องเข้าถึงได้ตามสิทธิ์

ปัจจุบันโค้ดเป็น Next.js เริ่มต้น ยังไม่มีการยืนยันตัวตน ฐานข้อมูล หรือกระบวนการออกเลข เอกสารภาพรวมระบบเดิมเป็นข้อมูลประกอบการออกแบบ มิใช่กติกาทั้งหมดที่ได้รับการยืนยันสำหรับระบบใหม่

## Solution

คำยืนยันล่าสุด 12 พฤศจิกายน 2026: พัฒนา UI และล็อกอินด้วยบัญชีสังเคราะห์ใน localhost ต่อได้โดยไม่รอเชื่อมบัญชีคณะจริง เริ่ม T04 รุ่น local จากกฎ T02 ที่รับรองแล้ว แยกหลักฐานบัญชีจริงและการตรวจ production ไม่มี test bypass เป็น [T13](../tickets/13-faculty-identity-release-gate.md) ที่ต้องผ่านก่อนเปิดใช้งาน T02 ยัง 4/5 จน AC1 มีหลักฐานจริง ไม่เพิ่ม SSO หรือระบบบัญชี production ใหม่เอง

แนวทางที่ผู้ใช้ยืนยันเพิ่มเติม 12 พฤศจิกายน 2026: ยึดระบบเดิมเป็นหลักและเปลี่ยน UI เป็นหลัก โดยตรวจขั้นตอนทำงาน วิธีล็อกอิน ข้อมูล และสิทธิ์จากระบบเดิมก่อน ไม่เพิ่ม SSO หรือเปลี่ยนกติกาธุรกิจเอง คงข้อสรุป T01/T02 ที่ผู้ใช้ยืนยันไว้แล้ว หาก source เดิมขัดกับข้อสรุปเหล่านี้ให้บันทึกความต่างก่อนเปลี่ยน พฤติกรรมที่เป็นช่องโหว่หรือเสี่ยงเลขซ้ำต้องแก้โดยรักษาการใช้งานเดิมให้มากที่สุด แนวทางนี้ไม่ได้อนุมัติการเชื่อม production การย้ายข้อมูลจริง หรือรับรองว่า source local ตรงกับ production

สร้างเว็บแอปพลิเคชันสำหรับบุคลากรภายในคณะ รองรับการออกเลขปกติ การออกเลขย้อนหลัง การบันทึกข้อมูลและไฟล์แนบ การค้นหา และการแก้ไขตามสิทธิ์ โดยใช้ระบบเดิมเป็นฐานทบทวนความต้องการ

ขอบเขตที่ยืนยันแล้วคือระบบใหม่ทดแทนระบบเดิมและใช้ภายในคณะเท่านั้น ความสามารถจากระบบเดิมในรายการด้านล่างเป็นขอบเขตเสนอสำหรับรุ่นแรก ต้องไม่ตีความว่ากฎการออกเลขหรือสิทธิ์ที่ยังเปิดอยู่ได้รับอนุมัติแล้ว

## User Stories

1. As an บุคลากรภายในคณะ, I want to เข้าสู่ระบบด้วยบัญชีที่คณะยอมรับ, so that เข้าใช้งานในนามของตนเองได้
2. As an บุคลากรภายในคณะ, I want to ออกจากระบบ, so that ผู้อื่นไม่ใช้สิทธิ์ของฉันผ่านเครื่องที่ใช้งานร่วมกัน
3. As an บุคลากรภายในคณะ, I want to เห็นรายการขอเลขล่าสุดของตน, so that ตรวจสอบงานที่เพิ่งทำได้รวดเร็ว
4. As an บุคลากรภายในคณะ, I want to เลือกประเภทหนังสือ, so that ขอเลขในชุดที่ถูกต้องตามกติกาที่ตกลง
5. As an บุคลากรภายในคณะ, I want to ขอเลขหนังสือสำหรับวันที่ปัจจุบัน, so that จัดทำหนังสือประจำวันได้
6. As an บุคลากรภายในคณะ, I want to ระบุเรื่องหนังสือ, so that ค้นหาและแยกแยะเอกสารได้
7. As an บุคลากรภายในคณะ, I want to ระบุผู้รับหลายคน, so that บันทึกผู้รับได้ครบถ้วน
8. As an บุคลากรภายในคณะ, I want to เลือกหน่วยงานรับเรื่องภายในคณะหลายหน่วยงาน, so that บันทึกปลายทางได้ตรงจริง
9. As an บุคลากรภายในคณะ, I want to ระบุหน่วยงานรับเรื่องภายนอกคณะ, so that จัดทำหนังสือถึงหน่วยงานภายนอกได้
10. As an บุคลากรภายในคณะ, I want to ระบุผู้ลงนามและตรวจสอบผู้ขอเลข, so that ข้อมูลผู้เกี่ยวข้องถูกต้อง
11. As an บุคลากรภายในคณะ, I want to กำหนดการเผยแพร่หนังสือ, so that ข้อมูลปรากฏต่อผู้มีสิทธิ์ตามขอบเขตที่ตกลง
12. As an บุคลากรภายในคณะ, I want to ระบุสถานะความลับ, so that รายละเอียดได้รับการป้องกันตามกติกาที่ตกลง
13. As an บุคลากรภายในคณะ, I want to เห็นข้อผิดพลาดของแบบฟอร์มก่อนออกเลข, so that แก้ข้อมูลได้โดยไม่สร้างรายการผิดพลาด
14. As an บุคลากรภายในคณะ, I want to เห็นผลและเลขที่ได้รับหลังบันทึกสำเร็จ, so that นำไปใช้กับเอกสารได้
15. As an บุคลากรภายในคณะ, I want to ได้เลขไม่ซ้ำแม้มีผู้อื่นขอพร้อมกัน, so that อ้างอิงหนังสือได้อย่างแน่นอน
16. As an บุคลากรภายในคณะ, I want to ทราบผลเมื่อเครือข่ายขัดข้องหรือส่งคำขอซ้ำ, so that ตรวจสอบรายการเดิมได้ก่อนขออีกครั้ง
17. As an บุคลากรภายในคณะ, I want to ขอเลขย้อนหลังเมื่อมีสิทธิ์ตามกติกาที่ตกลง, so that รองรับงานที่ต้องอ้างวันที่ก่อนปัจจุบัน
18. As an บุคลากรภายในคณะ, I want to แนบ PDF ให้หนังสือของตน, so that จัดเก็บเนื้อหาเอกสารร่วมกับประวัติเลข
19. As an บุคลากรภายในคณะ, I want to ทราบสาเหตุที่ไฟล์แนบถูกปฏิเสธ, so that แก้ชนิดหรือขนาดไฟล์ได้
20. As an บุคลากรภายในคณะ, I want to เห็นสถานะความครบถ้วนของไฟล์แนบ, so that กลับมาจัดการรายการที่ค้างได้
21. As an บุคลากรภายในคณะ, I want to ค้นหาตามปี ประเภท เลข ช่วงวันที่ เรื่อง และผู้ขอเลข, so that พบเอกสารที่มีสิทธิ์เข้าถึง
22. As an บุคลากรภายในคณะ, I want to เปิดรายละเอียดและดาวน์โหลดไฟล์เฉพาะรายการที่มีสิทธิ์, so that เข้าถึงเอกสารที่เกี่ยวข้องได้อย่างปลอดภัย
23. As an บุคลากรภายในคณะ, I want to แก้ไขข้อมูลหนังสือของตนภายในขอบเขตที่อนุญาต, so that แก้ข้อผิดพลาดโดยยังตรวจสอบประวัติได้
24. As an บุคลากรภายในคณะ, I want to เห็นเหตุผลที่ไม่สามารถออกเลขได้, so that ทราบข้อจำกัดด้านสิทธิ์ วัน หรือเวลาตามกติกาที่ตกลง
25. As an บุคลากรภายในคณะ, I want to ใช้งานผ่านมือถือและคีย์บอร์ดได้, so that ทำงานได้ในอุปกรณ์และวิธีเข้าถึงที่เหมาะกับตน
26. As an บุคลากรภายในคณะ, I want to เห็นสถานะกำลังทำงาน ไม่มีข้อมูล และเกิดข้อผิดพลาดอย่างชัดเจน, so that ทราบผลการทำงานและดำเนินการต่อได้

## Implementation Decisions

### ข้อกำหนดที่ยืนยันแล้ว

- T03 รอบสาม 12 พฤศจิกายน 2026: เฉพาะเจ้าของแก้เรื่อง ผู้รับ หน่วยงานรับเรื่อง ผู้ลงนาม ความลับ เผยแพร่ และ PDF ห้ามแก้เจ้าของ ชุดเลข ปี เลขหลัก/ย่อย วันที่หนังสือและเวลาออกจริง ใช้ version ตรวจแก้ชนกัน ให้คำขอ version เก่าโหลดใหม่ เก็บก่อน/หลังพร้อม audit แบบ atomic
- PDF ที่แนบต้องไม่เกิน 2,097,152 bytes (2 MiB รวมขอบ) ตรวจ MIME/โครงสร้างฝั่ง server ปฏิเสธไฟล์เสีย/เข้ารหัส ไฟล์ใหม่ไม่ผ่านให้คงไฟล์เดิม ไม่ลับปกติ/ย้อนหลังออกเลขก่อนแนบ PDF ภายหลัง หากผู้ทำรายการมีไม่ลับค้างไฟล์ให้บล็อกคำขอเลขใหม่ก่อนจัดสรรทั้งสองเส้นทาง ลับทั้งสองแบบยกเว้นไฟล์ เปลี่ยนลับเป็นไม่ลับโดยไม่มี PDF ให้ค้างไฟล์ ไม่คืนเลข T10 ต้องรอ T07 ส่วน T05 ไม่รอ T07 เพื่อไม่เกิด dependency cycle

- T03 รอบสอง 12 พฤศจิกายน 2026: เลือกต้นทางที่อ่านได้และใช้ชุดได้ คงชุด/ปี/วันที่/เลขหลัก เพิ่มเลขย่อยจำนวนเต็ม .1, .2, … .10 ขอพร้อมกันไม่ซ้ำ ไม่กระทบเลขหลัก ไม่เติมช่องว่าง อนุญาตทุกปีที่มีต้นทางย้อนหลังที่อ่านได้ ไม่มีต้นทางวันที่ต้องการให้ปฏิเสธ; คำขอเดิมส่งซ้ำคืนรายการเดิม รหัสเดิมข้อมูลต่างปฏิเสธ ก่อนบันทึกสำเร็จล้มเหลว rollback หนังสือ/ตัวนับ/audit ทั้งชุดไม่ถือว่าออกเลขแล้ว หลังบันทึกสำเร็จตอบกลับหาย retry คืนเลขเดิม แนบไฟล์ล้มเหลวให้แนบใหม่รายการเดิม ไม่คืนเลข/เติมช่องว่าง ทั้งหมดรอพัฒนาและทดสอบจริง

- T03 คำยืนยันรอบแรก 12 พฤศจิกายน 2026: ผู้มีสิทธิ์ใช้ชุดเลขขอย้อนหลังได้ทันที ไม่ต้องรออนุมัติ; รุ่นแรกไม่มีฟังก์ชันยกเลิก (T11 ไม่ดำเนินการ ไม่ใช่งานเสร็จ); หนังสือลับทั้งปกติและย้อนหลังยกเว้น PDF หากมีไฟล์ยังตรวจสิทธิ์ T02 ฟิลด์แก้ไขและ PDF รับรองเพิ่มครบตามรอบสามใน [T03](../tickets/Done-03-document-exceptions.md)

- T02: ผู้ใช้ยืนยัน 12 พฤศจิกายน 2026 ว่าไม่ลับ/ไม่เผยแพร่อ่านได้โดยเจ้าของและบุคลากรหน่วยงานเดียวกัน; ไม่ลับ/เผยแพร่อ่านได้ทั้งคณะ; ลับอ่านได้เฉพาะเจ้าของแม้ตั้งเผยแพร่ กฎเดียวกันครอบคลุมรายการค้นหา จำนวนผล รายละเอียดและ PDF เฉพาะเจ้าของแก้ข้อมูล/ไฟล์/ความลับ/เผยแพร่และอ่าน audit ของตน ผู้ดูแลข้อมูลอ้างอิงไม่มีสิทธิ์อ่านลับหรือแก้แทนโดยอัตโนมัติ
- T02 คำยืนยันเพิ่มเติม 12 พฤศจิกายน 2026: ผู้ดูแลระบบมอบถอนผู้จัดการชุดเลข ผู้จัดการมอบถอนผู้ใช้เลขได้เฉพาะชุดของตน ทุกการเปลี่ยนเก็บ audit ไม่เพิ่มสิทธิ์อ่านลับ/แก้แทน การแต่งตั้งผู้ดูแลใหม่ต้องเจ้าของระบบอนุมัติ เมื่อย้ายหน่วยงานคงเจ้าของและหน่วยงานเดิมกับหนังสือ ใช้หน่วยงานปัจจุบันของผู้อ่านตรวจสิทธิ์ grants ไม่ย้ายตามอัตโนมัติให้ผู้ดูแลทบทวน เมื่อระบบรับรู้พ้นสภาพปิด session แต่คงประวัติ ผู้ใช้ระบุว่ามีสภาพแวดล้อมทดสอบแล้ว ยังรอรายละเอียดและหลักฐานเชื่อม identity ตาม [T02](../tickets/02-identity-permissions.md)

- คำยืนยันเพิ่มเติม 12 พฤศจิกายน 2026 (รายละเอียด/ตัวอย่างตรวจรับใน T01): คงขอบเขตชุดเลขเดิมตาม `bookdept` + ปี, prefix เดิม, ลำดับขั้นต่ำ 4 หลัก และออกเลขทันทีสำหรับบุคลากรที่ได้รับสิทธิ์ชุดนั้น ผู้ดูแลระบบจัดการหน่วยงาน ประเภท และชุดเลข
- หน่วยงานทั่วไปออกเลขได้ทุกวัน 07:00:00–22:30:59 ตาม Asia/Bangkok รวมวินาทีปลาย การเงิน/พัสดุคงข้อยกเว้นเดิมรหัส204ได้ตลอดเวลา ไม่งดเสาร์อาทิตย์/วันหยุด ไม่ใช้ประกาศวันหยุด ตรวจสิทธิ์และเวลาขณะจัดสรรใน transaction คำขอที่มาถึงทันแต่จัดสรรหลังเวลาปิดต้องปฏิเสธโดยไม่สร้างหนังสือหรือจัดสรรเลข (ยกเว้นเวลาเฉพาะการเงิน/พัสดุ ไม่ยกเว้นสิทธิ์ชุด)
- คงปีปฏิทิน พ.ศ. ตามเดิม เปลี่ยนรอบ 1 มกราคมตาม Asia/Bangkok; คำสั่ง00006อิงปีของวันที่หนังสือ; รอบใหม่ที่ไม่มีรายการเริ่ม0001 ลำดับเกิน9999เป็น10000 พักชุด00047ที่ปี/prefixว่างจนผู้ดูแลยืนยัน ไม่เปิดปีงบประมาณเพิ่มเติมเพียงเพราะโค้ดรองรับ สิทธิ์/อัลกอริทึมย้อนหลังและข้ามปีรับรองแล้วตาม T03; T10 เป็นงานพัฒนา
- ยืนยันย้ายประวัติเดิมและเดินเลขต่อหลังตรวจยอด: ซ้อมย้าย คงเลข/source ID ตรวจกลุ่มผิดปกติโดยไม่renumberอัตโนมัติ หยุดรับเลขระบบเก่า ดึงข้อมูลรอบสุดท้ายและรับรองตัวนับรายชุด/ปี เปิดใหม่เพียงระบบเดียวโดยเก่าคงอ่านอย่างเดียว หากยอดไม่ตรงยังไม่เปิดใช้ วันcutover ผู้รับรอง คำขอค้าง และrollbackรายละเอียดต้องตรวจรับในT12ก่อนรันจริง การยืนยันแนวทางนี้ไม่ใช่การอนุมัติproduction migration

- รุ่นแรกทดแทนระบบเดิมและรองรับเฉพาะบุคลากรภายในคณะวิศวกรรมศาสตร์ มหาวิทยาลัยสงขลานครินทร์
- ใช้ Next.js App Router, TypeScript, MySQL และ CoreUI ตามแนวทางโปรเจกต์ ไม่อัปเกรด dependency โดยไม่ได้รับอนุมัติ ปัจจุบัน MySQL driver และ CoreUI ยังไม่ได้ติดตั้ง
- ใช้ Asia/Bangkok สำหรับวันที่และเวลาทางธุรกิจ แยกวันที่หนังสือออกจากเวลาที่เกิดเหตุการณ์จริง
- เก็บ secrets และการเข้าถึงฐานข้อมูลฝั่ง server ตรวจ input และ authorize ทุก protected operation รวมการค้นหา รายละเอียด และดาวน์โหลด
- การจัดสรรเลขต้องใช้ transaction และกลไกควบคุมการแข่งขัน พร้อมข้อจำกัด unique ใน MySQL ห้ามใช้ MAX+1 เพียงอย่างเดียว
- เก็บ audit history สำหรับการออกเลข การแก้ไข การยกเลิก และการเปลี่ยนแปลงด้วยสิทธิ์พิเศษ ห้ามนำเลขยกเลิกหรือผิดพลาดกลับมาใช้โดยเงียบ ๆ

### โครงสร้างเสนอเพื่อพัฒนาต่อ

- แบ่งความรับผิดชอบเป็น identity/access, ข้อมูลหนังสือ, การจัดสรรเลข, ไฟล์แนบ, การค้นหา และ audit ใช้ภายในแอปเดียวก่อน โดยยังไม่กำหนดให้แยกเป็นบริการภายนอก
- ใช้ Server Components เป็นหลัก แยกส่วนโต้ตอบของ CoreUI เป็น Client Components ขนาดเล็ก
- แบบจำลองข้อมูลเสนอประกอบด้วยผู้ใช้งาน หน่วยงาน ประเภทหนังสือ ชุดเลข/รอบเลข หนังสือ ผู้รับ ไฟล์แนบ และเหตุการณ์ audit ความสัมพันธ์และคีย์ unique ขั้นสุดท้ายต้องรอการยืนยันขอบเขตชุดเลข
- แยกสถานะการจัดสรรเลข ความครบถ้วนของไฟล์ ความลับ และการเผยแพร่ ไม่ใช้สถานะเดียวแทนทุกความหมาย
- การยืนยันตัวตนมีขอบเขตเชื่อมต่อระบบบัญชีของคณะ แต่ยังไม่เลือก protocol หรือสร้างระบบเก็บรหัสผ่านขึ้นเอง
- การจัดสรรเลขกับการบันทึกหนังสือต้องมีผล atomic ที่ฐานข้อมูล ส่วนไฟล์แนบอาจอยู่คนละระบบจัดเก็บ จึงต้องออกแบบการกู้คืนเมื่อไฟล์หรือฐานข้อมูลผิดพลาด
- API และหน้าจอต้องให้ผลสำเร็จ/ข้อผิดพลาดชัดเจน ไม่รั่ว secrets หรือข้อมูลหนังสือที่ไม่มีสิทธิ์เห็น ยังไม่ตรึง endpoint หรือ schema จนกติกาหลักชัดเจน

### ข้อมูลจากระบบเดิมที่ต้องทบทวนก่อนใช้จริง

ตรวจ source PHP ที่ผู้ใช้ระบุและ SQL snapshot เพิ่มเติมเมื่อ 11 พฤศจิกายน 2026 ดู [ผลวิเคราะห์พร้อมแหล่งอ้างอิง](./legacy-numbering-analysis.md) พบรายละเอียดชุดเลข/ปี ข้อยกเว้นวันเวลา และข้อจำกัดการจัดสรร ข้อมูลนี้ยังไม่เปลี่ยนสถานะคำถามเปิดเป็นคำยืนยันระบบใหม่

- บัญชี Intranet; dashboard ล่าสุด 3 รายการ; ประเภทตัวอย่าง ศธ และ มอ
- ออกเลขเฉพาะ 07:00–22:30 ไม่ออกในวันเสาร์ อาทิตย์ และวันหยุดที่ประกาศ ต้องยืนยันการนับเวลาขอบเขตและแหล่งปฏิทินวันหยุด
- เดิมระบุ PDF 2 MB; ผู้ใช้ยืนยัน T03 รอบสามให้ใช้ 2 MiB = 2,097,152 bytes รวมขอบ และตรวจ MIME/โครงสร้าง ปฏิเสธเสีย/เข้ารหัสแล้ว
- ข้อขัดแย้ง PDF ลับย้อนหลังปิดตาม T03: ลับทั้งสองแบบยกเว้น PDF ไม่ลับทั้งสองแบบแนบหลังออกเลข และค้างไฟล์ของผู้ทำรายการบล็อกคำขอเลขถัดไป
- ไม่เผยแพร่เป็นค่าตั้งต้นตามเอกสารเดิม; ผู้ใช้ยืนยันตารางอ่านใน/นอกหน่วยงานและกฎเปลี่ยนสังกัดแล้วในT02 ส่วนการจับคู่รหัสหน่วยงานจริงยังรอหลักฐาน identity
- เลขย้อนหลังรับรองกติกาใน T03 รอบสองแล้ว ใช้ต้นทางที่อ่านได้ในชุดที่มีสิทธิ์ เพิ่มเลขย่อยจำนวนเต็มโดยไม่เปลี่ยนปี/วันที่/เลขหลัก ไม่เติมช่องว่าง

## Testing Decisions

- ผู้ใช้ยืนยันแล้ว: ใช้ขอบเขตทดสอบหลักที่พฤติกรรมผู้ใช้ผ่านเว็บและ HTTP ของระบบจริง ทดสอบการเข้าสู่ระบบ ขอเลข ค้นหา แก้ไข แนบไฟล์ และการถูกปฏิเสธสิทธิ์ โดยใช้ MySQL แยกสำหรับทดสอบ
- เพิ่ม HTTP integration tests เฉพาะสถานการณ์ที่เว็บทดสอบได้ไม่ชัด ได้แก่คำขอพร้อมกัน การส่งซ้ำ และความล้มเหลวระหว่าง transaction ตรวจผลผ่านข้อมูลหนังสือและ audit ที่ระบบเปิดให้ผู้มีสิทธิ์อ่าน แทนการผูกเทสต์กับชื่อฟังก์ชันภายใน
- เทสต์ที่ดีตรวจพฤติกรรมที่สังเกตได้ ไม่ทดสอบตามรายละเอียด implementation และต้องยังมีคุณค่าเมื่อ refactor
- กลุ่มที่ครอบคลุม: identity/access, หนังสือ/การจัดสรรเลข, ไฟล์แนบ, ค้นหา และ audit ผ่านขอบเขตสาธารณะของระบบ
- ทดสอบเลขไม่ซ้ำเมื่อแข่งขันในชุดเดียวกัน การแยกชุดตามกติกาที่อนุมัติ และ rollback ที่ไม่ทิ้งหนังสือ/เลข/audit ขัดแย้งกัน นโยบายเลขขาดช่วงและ retry รับรองแล้วใน T03 รอบสอง ใช้ตัวอย่าง X05/X06 ตรวจรับ
- ทดสอบกรณีข้ามวัน/ปีตาม Asia/Bangkok วันหยุดและขอบเวลา เมื่อกติกานั้นได้รับการยืนยัน
- ทดสอบการเข้าถึงข้ามเจ้าของ/หน่วยงาน/ความลับ ทั้งหน้ารายการ จำนวนผลค้นหา รายละเอียด และ URL ไฟล์โดยตรง หลังยืนยันตารางสิทธิ์
- ทดสอบ PDF ผิดชนิด เกินขนาด และไฟล์ที่ไม่มีสิทธิ์ พร้อมกรณีหนังสือลับ/ย้อนหลังหลังแก้ข้อขัดแย้ง
- ปัจจุบันไม่มีชุดเทสต์หรือ test runner ที่ใช้อ้างอิงได้ ต้องเพิ่มเครื่องมือตามแนวทาง testing ของโปรเจกต์ ตรวจ lint, typecheck และเทสต์ที่เกี่ยวข้องก่อนส่ง QA
- ไม่ใช้บัญชีหรือข้อมูล production ในเทสต์ และไม่สมมติว่าระบบ identity จริงพร้อมใช้งาน ต้องมีขอบเขตทดสอบสำหรับ identity พร้อมตรวจ integration ก่อนเปิดจริง

## Out of Scope

- ผู้ใช้ภายนอกคณะ การรองรับหลายคณะ และการเปิดเอกสารต่อสาธารณะ
- การเขียนโค้ดระบบจริง การรัน migration การแก้ข้อมูล production และการ deploy ภายใต้งานจัดทำสเปกนี้
- การกำหนดแทนเจ้าของเรื่องเลขย้อนหลัง ปีที่ใช้/reset prefix การอนุมัติ การยกเลิก/ใช้เลขซ้ำ สิทธิ์พิเศษ และการย้ายข้อมูล
- ฟังก์ชันใหม่ที่ยังไม่ตกลง เช่นลายเซ็นดิจิทัล workflow อนุมัติ และการแจ้งเตือนผ่านบริการภายนอก
- การประดิษฐ์ข้อกำหนดด้านกฎหมายหรือระยะเวลาเก็บข้อมูล
