# T08 — ค้นหาหนังสือตามสิทธิ์ รุ่น local

พัฒนาเมื่อ 13 พฤศจิกายน 2026 (Asia/Bangkok) ใช้บัญชีและ MySQL สังเคราะห์เดิม ไม่มีการเปลี่ยน schema หรือ migration

## วิธีใช้งาน

หน้าออกเลขเอกสารใช้ความกว้างเนื้อหาสูงสุด 1,120px เท่าหน้าหลัก และจัดกึ่งกลางตรงแนวเมนูทั้งโหมดอ่านหนังสือเดิมและโหมดออกเลข

หน้ารายละเอียดหนังสือใช้กรอบกึ่งกลางกว้างสูงสุด 880px พร้อมระยะขอบภายในที่กระชับ บนมือถือข้อมูลเรียงหนึ่งคอลัมน์และกรอบย่อตามพื้นที่หน้าจอ

ปรับหน้ารายการเมื่อ 19 พฤศจิกายน 2569: ตารางกว้างสูงสุด 1,120px จัดแนวกับเมนูด้านบน แสดง 4 คอลัมน์ ได้แก่ เลขหนังสือ/ปี วันที่หนังสือ เรื่อง และรายละเอียด วันที่แสดงเป็นวัน-เดือน-ปี พ.ศ. เช่น `18-11-2569` โดยยังเรียงจากวันที่จริงบนเซิร์ฟเวอร์ ปีเลขยังใช้ค่าที่บันทึกไว้แยกจากปีวันที่ มีปุ่ม “ออกเลขหนังสือ” ข้างหัวข้อเหนือช่องค้นหาไปที่ `/workspace/issuance` และคงเมนูเดิมไว้ ตัวกรองผู้ขอเลข/ประเภทและข้อมูลในหน้ารายละเอียดยังคงเดิม

เลขหนังสือและปุ่ม “ดูรายละเอียด” เปิดหน้าแยกในแท็บเดิมที่ `/workspace/documents/issuance/{id}` หรือ `/workspace/documents/legacy/{sourceId}?snapshot={sha256}` หน้ารายการจะไม่แสดงรายละเอียดต่อท้ายตารางอีก มีปุ่ม “กลับหน้ารายการ” และเก็บคำค้น ตัวกรอง ลำดับเรียง ขนาดหน้า และหน้าปัจจุบันที่ยืนยันแล้วใน URL เพื่อรองรับกลับรายการและรีเฟรช โดยไม่เก็บผลข้อมูลที่เสร็จแล้วเป็น cache

หน้ารายละเอียดตรวจ session และขอบเขตบุคลากร/หน่วยงาน แล้วเรียก API เดิมที่ตรวจสิทธิ์อีกครั้ง แยกหมวดข้อมูลหนังสือ ผู้รับ/ปลายทาง ไฟล์แนบ และบันทึกต้นทาง ข้อมูลที่ยังไม่ตรวจรับยังแสดงข้อจำกัดตามเดิม หนังสือระบบใหม่คงการดาวน์โหลด PDF ประวัติแก้ไข และการแก้ไขเฉพาะเจ้าของ ไม่มีการเพิ่มสิทธิ์หรือเปลี่ยนกติกาเลข ลิงก์กลับรับเฉพาะ path `/workspace` ภายในระบบ เมื่อรายละเอียดไม่พร้อมมีปุ่มลองใหม่ ส่วนไม่มีสิทธิ์หรือไม่พบรายการแสดงข้อความเดียวกัน

ใน `/workspace` ใช้ส่วน “ค้นหาหนังสือตามสิทธิ์” ระบบโหลดรายการ ประเภท และปีที่คุณอ่านได้อัตโนมัติเมื่อเปิดหน้า พิมพ์เลขหรือชื่อเรื่องแล้วกด Enter เพื่อค้นหา ปุ่ม “ตัวกรอง” เปิดกล่องลอยสำหรับปี ประเภท ช่วงวันที่ และรหัสผู้ขอเลข ค่าที่แก้ยังไม่ค้นหาจนกด “ใช้ตัวกรอง” และยังแสดงรายการเดิมอยู่ ปิดกล่องหรือกด Escape จะยกเลิกค่าที่ยังไม่ใช้ การแบ่งหน้าใช้ตัวกรองและการเรียงชุดที่ยืนยันแล้ว เลือกหน้าละ 20/50/100 รายการได้ (เริ่มต้น 20) เปิดผลค้นหาเพื่ออ่านรายละเอียดได้ทั้งหนังสือใหม่และประวัติเดิม

`GET /api/search` รับพารามิเตอร์ที่ใช้ร่วมกันแบบ AND:

| พารามิเตอร์ | ความหมาย |
|---|---|
| `q` | ข้อความบางส่วนในเลขหนังสือหรือชื่อเรื่อง (OR) สูงสุด 200 ตัวอักษร |
| `year` | ปีเลข พ.ศ. 4 หลัก จาก `number_year` ที่บันทึกไว้ ไม่คำนวณจากวันที่หนังสือ |
| `type` | ประเภทหนังสือตรงตัวจาก `issuance_series.document_type` |
| `number` | ส่วนหนึ่งของเลขที่แสดง รวม prefix เลขหลักอย่างน้อย 4 หลัก และเลขย่อย เช่น `0042.10` สูงสุด 100 ตัวอักษร |
| `from`, `to` | วันที่หนังสือ `YYYY-MM-DD` ค.ศ. รวมวันเริ่ม/สิ้นสุด ใส่เพียงด้านเดียวได้ |
| `subject` | ส่วนหนึ่งของเรื่อง สูงสุด 200 ตัวอักษร |
| `requester` | รหัสบุคลากรผู้ขอเลขตรงตัว สูงสุด 64 ตัวอักษร ไม่มีการสร้างชื่อผู้ขอจากข้อมูลที่ไม่มี |
| `page` | จำนวนเต็ม 1–10000 ค่าเริ่มต้น 1 |
| `pageSize` | 20, 50 หรือ 100 ค่าเริ่มต้น 20; ปฏิเสธค่าอื่นและพารามิเตอร์ซ้ำ |
| `sort` | ส่งคู่กับ `direction`: `number`, `documentDate`, `subject`, `ownerId`, `type` |
| `direction` | `asc` หรือ `desc` เรียงหลังกรองสิทธิ์และก่อนแบ่งหน้า ครอบคลุมผลทั้งหมด |

ตารางค้นหาใช้ AG Grid Community 36.3.0 ปรับความกว้างคอลัมน์ได้ กดหัวคอลัมน์เพื่อเรียงขึ้น/ลง จะกลับหน้า 1 และคงตัวกรองไว้ ปุ่มแบ่งหน้าด้านล่างใช้ลำดับเดียวกัน เลขหนังสือกดหรือใช้ Enter เพื่อเปิดรายละเอียดได้ ไม่โหลดข้อมูลทั้งหมดมายังเบราว์เซอร์ การเรียงเลขเปรียบเทียบปี prefix เลขหลัก และเลขย่อยแบบตัวเลข หากไม่ส่งการเรียง API ใช้วันที่ใหม่ไปเก่าตามเดิม

รูปแบบตามภาพอ้างอิงปรับวันที่ 19 พฤศจิกายน 2569: แถบค้นหาแยกจากตาราง หัวตารางสีอ่อน แถวกระชับ เลขหนังสือเป็นข้อความกดได้และมีปุ่ม “ดูรายละเอียด” ท้ายแถว ตาราง AG Grid ขยายสูงตามรายการในหน้านั้นโดยไม่มี scroll แนวตั้งภายใน แถบล่างแสดงยอด จำนวนต่อหน้า และปุ่มเลขหน้า ตัวอักษรหลักทั่วระบบและในตารางเพิ่มเป็น 17px หัวข้อหลักประมาณ 25px แถบบนแสดงชื่อระบบและชื่อผู้ใช้ ส่วนชื่อคณะและหน่วยงานใต้ชื่อผู้ใช้ถูกนำออกเฉพาะแถบบน ข้อมูลหน่วยงานในรายละเอียดเอกสารยังแสดงตามเดิม

เมื่อใช้ `BOOK_DATA_PROVIDER=ronaldo` ต้อง build และ restart บริการ Ronaldo เพื่อรับพารามิเตอร์การเรียงใหม่ ไม่มีการเปลี่ยน schema หรือ migration

ช่องว่างหัวท้ายถูกตัดออก คำค้น `%`, `_` และ SQL syntax เป็นข้อความตามตัวอักษร ปฏิเสธวันที่ที่ไม่มีจริง ช่วงวันกลับด้าน ปี/หน้าไม่ถูกต้อง พารามิเตอร์ซ้ำ ไม่รู้จัก หรือยาวเกินกำหนดด้วย 400 ไม่มี session คืน 401 ระบบขัดข้องคืน 503 ทุก response ใช้ no-store

ผลลัพธ์มี `documents`, `total`, `page`, `pageSize`, `hasMore`, `types`, `years` หน้าที่เกินผลจริงคืนรายการว่างพร้อมยอดที่อ่านได้ วันที่ใช้วันที่หนังสือที่บันทึกตามกติกาธุรกิจ ไม่เปลี่ยนเป็น UTC; เวลาออกเลขจริงในรายละเอียดแปลงจาก UTC เป็น Asia/Bangkok

## สิทธิ์และความถูกต้อง

- รวม `issuance_documents` และ `legacy_documents` ที่ normalize/ตรวจรับแล้วแบบ UNION ALL เก็บประวัติเลขซ้ำและสถานะยกเลิกตามต้นทาง ไม่รวม raw/staging/disposition/reservations
- เจ้าของอ่านได้ ผู้อื่นอ่านเฉพาะไม่ลับและ (เผยแพร่หรือหน่วยงานปัจจุบันตรงหน่วยงานผู้ขอ ณ วันออก) ตาม T02 ลับเหนือเผยแพร่
- กรองสิทธิ์ก่อนนับ แบ่งหน้า และสร้างรายการประเภท/ปี ไม่มีการส่งยอดหรือประเภทจากหนังสือที่ซ่อน
- ยอด ผลแต่ละหน้า และตัวเลือกประเภท/ปีอ่านใน transaction เดียวกันแบบ REPEATABLE READ เรียงวันที่ ปี ชุด เลขหลัก เลขย่อย และ identity ต้นทางเพื่อให้ลำดับคงที่
- ไม่จำกัดการอ่านด้วย grant ออกเลขหรือสถานะเปิดชุดเลข หนังสือในชุดที่ปิดแล้วยังค้นได้ตามสิทธิ์อ่าน
- เปิดรายละเอียดผ่าน endpoint เดิมที่ตรวจสิทธิ์ใหม่ทั้งหนังสือใหม่และประวัติเดิม 404 เมื่อไม่พบหรือไม่มีสิทธิ์ ไม่มี audit ของคนอื่น
- UI ล้างรายละเอียดก่อนโหลดใหม่และล้างผลเมื่อเปิดแล้วถูกปฏิเสธ มี loading/error, focus รายละเอียด/ข้อผิดพลาด และปุ่ม/label สำหรับคีย์บอร์ด

## การตรวจสอบ

กล่องตัวกรองปิดเมื่อเลื่อนหน้า/พื้นที่ด้านนอกกล่องหรือปรับขนาดหน้าจอ เพื่อไม่ให้ค้างกลางตาราง การเลื่อนภายในกล่องบนจอเล็กยังทำงานและไม่ปิดกล่อง กำหนด `overscroll-behavior: contain` เพื่อไม่ให้การเลื่อนภายในส่งต่อไปยังหน้า ทดสอบด้วยกรณี `filter popover closes on page scrolling but stays open during internal scrolling` ใน `tests/search.spec.mjs`

แก้ timeout ในโหมด Ronaldo วันที่ 19 พฤศจิกายน 2569: ข้อมูล clone จริงมีประมาณ 172,000 แถว เดิมค้นหนึ่งครั้งสแกน 4 รอบ ใช้ SQL ราว 6.2 วินาทีและคำขอพร้อมกันเกินเวลารอ 8 วินาที บริการรวมยอดที่ตรงตัวกรองกับตัวเลือกประเภท/ปีที่อ่านได้ไว้ใน aggregate เดียว เหลือ 2 query รวมหน้ารายการ โดยไม่เปลี่ยนสิทธิ์หรือตัวกรอง ตัวเชื่อมรอสูงสุด 30 วินาที และรวมเฉพาะคำขอที่กำลังรอผลซึ่งมี staffId, departmentId, operation และ payload เดียวกัน ไม่เก็บผลที่เสร็จแล้วหรือข้อผิดพลาดเป็น cache และคำขอหลังย้ายหน่วยงานจะไม่ใช้ผลจากขอบเขตเดิม ไม่มีการเปลี่ยน schema/index หรือเขียนข้อมูลต้นทาง

การปรับ UI วันที่ 19 พฤศจิกายน 2569: `npm.cmd run test:search` ตรวจ sort allowlist, ลำดับข้ามหน้า และสิทธิ์ด้วย MySQL สังเคราะห์; `npx.cmd playwright test tests/search.spec.mjs tests/auth.spec.mjs` ตรวจตาราง AG Grid, เรียงขึ้น/ลง, ความกว้างคอลัมน์หลังเปลี่ยนหน้า, ฟอนต์, มือถือ และการเรียงด้วยคีย์บอร์ดระหว่างรอรายละเอียด ภาพตรวจรับอยู่ `.local/ag-grid-desktop.png` และ `.local/ag-grid-mobile.png`

ตรวจรับ local และ QA อิสระผ่านเมื่อ 13 พฤศจิกายน 2026 ดู [ticket T08](../tickets/Done-08-search.md) เทสต์อยู่ `tests/search.spec.mjs` เปิด Next.js พอร์ต 3111 และ MySQL สังเคราะห์พอร์ต 3325 log และภาพมือถืออยู่ `.local/t08-e2e-server.log` และ `.local/t08-search-mobile.png`

- T08 browser/HTTP และ raw parser 8/8: ตัวกรองเดี่ยว/ร่วม สิทธิ์สองแหล่งข้อมูล ยอด/ประเภทไม่รั่ว แบ่งหน้า ข้อมูลผิด ปีเลขแยกจากปีวันที่ ข้อความพิเศษ ประวัติเลขซ้ำ/ยกเลิก ข้อมูลเก็บแยก มือถือ/คีย์บอร์ด loading/error และถอนสิทธิ์ก่อนเปิดรายละเอียด
- Regression เดิมจาก full E2E 44/44; provider 9/9; production isolation 3/3; lint/typecheck/build ผ่าน
- Full E2E รอบแรก 51/52 เนื่องจากสมมติฐานเทสต์ HTTP `__proto__` ไม่ตรง Next.js ซึ่ง normalize ชื่อนี้ทิ้งก่อนถึง route เปลี่ยนตรวจ parser โดยตรงและรัน T08 ใหม่ผ่านทั้ง 8 ไม่มีเทสต์ค้างล้มเหลว
- QA อิสระตรวจ SQL/สิทธิ์/วันเวลา/UI และเทสต์ ผ่านหลังแก้ allowlist ด้วย `Object.hasOwn` เพื่อปฏิเสธชื่อบน prototype

ไม่มี migration ใหม่ การค้นด้วยข้อความและยอดรวมยังต้องประเมินแผน query/index และเวลาใช้งานกับข้อมูลที่ตรวจรับก่อนเปิดจริง ขอบเขตรุ่น local ไม่ข้ามเงื่อนไข T12/T13

## การยุบฟอร์มค้นหา (17 พฤศจิกายน 2569)

แถวหลักแสดงช่อง `เลขหนังสือหรือชื่อเรื่อง` เพียงช่องเดียว, dropdown `ปีเลข (พ.ศ.)` และปุ่มค้นหา ช่องค้นหาใช้ `q` ยาวไม่เกิน 200 ตัวอักษร ค้นข้อความบางส่วนในเลขหนังสือที่แสดง **หรือ** ชื่อเรื่อง (OR ในวงเล็บ) โดยยัง AND กับตัวกรองอื่นและตรวจสิทธิ์บนเซิร์ฟเวอร์ `%` และ `_` เป็นข้อความตามตัวอักษร ไม่แยกคำค้นเป็นหลายคำ

ปีเริ่มต้นเป็น `ทุกปี` และตัวเลือกเรียงปีเลข พ.ศ. จากใหม่ไปเก่า เฉพาะปีที่มีหนังสือซึ่งบัญชีนั้นอ่านได้ รวมข้อมูลใหม่และประวัติเดิม รายการปีเป็นข้อมูล `years: number[]` จาก API คำนวณใน transaction เดียวกับผลค้นหาและประเภท และไม่เปลี่ยนตามคำค้น/ตัวกรองปัจจุบัน เพื่อไม่ให้ปีหายเมื่อค้นไม่พบ

ประเภทหนังสือ ช่วงวันที่ และรหัสผู้ขอเลขอยู่ใน `ค้นหาเพิ่มเติม` ซึ่งยุบไว้ตอนเริ่มต้น หากมีตัวกรองเพิ่มเติมที่กำหนดไว้จะแสดงจำนวนข้างหัวข้อ ล้างตัวกรองคืนช่องค้นหาว่าง/ทุกปี/ทุกประเภท/ไม่จำกัดวันที่หรือผู้ขอ พารามิเตอร์ API เดิม `number` และ `subject` ยังใช้ได้เพื่อความเข้ากันได้ แต่ฟอร์มใหม่ใช้ `q`
