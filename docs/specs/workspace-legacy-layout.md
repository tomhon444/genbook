# หน้าทำงานตามรูปแบบระบบเดิม

ข้อสรุปที่ผู้ใช้ยืนยันวันที่ 17 พฤศจิกายน 2569

- เมนูอยู่ด้านบน มีเพียง **หน้าหลัก** (`/workspace`) และ **หน้าออกเลขเอกสาร** (`/workspace/issuance`)
- หน้าหลักรวมค้นหาและประวัติจากระบบเดิม/ระบบใหม่ในตารางเดียว โหลดรายการตามสิทธิ์ทันที เรียงวันที่หนังสือใหม่ไปเก่า ล้างตัวกรองแล้วโหลดรายการทั้งหมดตามสิทธิ์อีกครั้ง
- ลิงก์เดิม `/workspace/search` และ `/workspace/history` ไปหน้าหลัก รายละเอียดประวัติเดิมยังแสดงผู้รับ ปลายทาง ผู้ลงนาม และเวลาต้นฉบับตามข้อมูลที่ตรวจรับแล้ว
- ซ่อนเมนูและลิงก์ข้อมูลผู้ใช้งาน คงชื่อ หน่วยงาน และปุ่มออกจากระบบไว้
- ชุดเลขมาจากสิทธิ์ของบัญชีที่เข้าสู่ระบบ หากมีชุดเดียวเลือกให้อัตโนมัติ หากมีหลายชุดผู้ใช้เลือกเอง หากไม่มีสิทธิ์ให้ติดต่อผู้ดูแล ตัวนับยังร่วมกันตามชุดเลขและปี

ลำดับฟอร์ม: **เลขหนังสือ → วิธีขอเลข/ต้นทางย้อนหลัง → การเผยแพร่ → ความลับ → วันที่ → เรื่อง → เรียน → หน่วยงานรับเรื่อง → ผู้ลงนาม → ผู้ขอเลข**

การเผยแพร่เริ่มที่ไม่เผยแพร่ ความลับเริ่มที่ไม่ลับ ผู้รับเพิ่ม/ลบเป็นแถวได้ สูงสุด 20 คน คนละ 200 ตัวอักษร รวมไม่เกิน 3,000 ตัวอักษร ส่งเข้า API เป็นข้อความคั่นบรรทัดเช่นเดิม ผู้ลงนามยังกรอกข้อความจนกว่าแหล่งรายชื่อ/ตำแหน่งปัจจุบันพร้อมใช้

วันที่ปกติเป็นวันปัจจุบันใน Asia/Bangkok และอ่านอย่างเดียว การย้อนหลังยังเลือกหนังสือต้นทางที่อ่านได้และมีสิทธิ์ใช้ชุดเลข โดยคงชุด ปี วันที่ และเลขหลัก แล้วจัดสรรเลขย่อย ชุดเลขด้านบนเปลี่ยนตามต้นทางที่เลือก

งานนี้เปลี่ยนหน้าจอและเส้นทาง ไม่เปลี่ยน schema การจัดสรรเลข สิทธิ์อ่าน/ออกเลข การตรวจไฟล์ หรือประวัติ audit และไม่ต้องย้ายข้อมูล

การตรวจรับครอบคลุมเมนู/มือถือ การโหลดและล้างตัวกรอง รายละเอียดเก่า การกันผลลัพธ์จากคำขอเก่าทับคำขอใหม่ ชุดเลขต่างบัญชี รูปแบบฟอร์ม ผู้รับหลายคน และชุดทดสอบการจัดสรรพร้อมกัน/ส่งซ้ำเดิม

## ผลตรวจ

- `npm.cmd run lint`, `npm.cmd run typecheck` และ `npm.cmd run build` ผ่าน
- `npm.cmd run test:issuance` ผ่าน 12 กรณี รวมการจัดสรรใน MySQL และกฎย้อนหลัง
- E2E 73 กรณี: ชุดเต็มผ่าน 72 กรณี กรณี auth มือถือติด selector ชื่อที่รวมข้อความหน่วยงาน หลังปรับ selector รันเฉพาะกรณีนี้ซ้ำผ่านแล้ว ไม่เปลี่ยน TTL หรือพฤติกรรมยืนยันตัวตน
- ตรวจภาพหน้าจอเดสก์ท็อป/มือถือ และ QA review ไม่เหลือข้อค้นพบค้าง
- การตรวจใช้บริการบัญชีและฐานข้อมูลสังเคราะห์แยกจากระบบจริง
