## ข้อเสนอเมื่อไม่มีหลักฐานกู้ข้อมูลเพิ่ม

ผู้ใช้ตอบ “ยืนยัน” ต่อแนวทางรักษาต้นฉบับ แยกข้อมูลที่ระบุตัวตน/ชุดไม่ได้ รักษาเวลาไม่ทราบ และกันเลขเดิม เมื่อ 13 พฤศจิกายน 2026 จึงรับรอง **แนวทางเก็บในตารางนี้** แล้ว ดู [ADR 0001](../adr/0001-preserve-unresolved-legacy-history.md) ไม่ถือว่าเป็นการยืนยันค่าทดแทนหรือจับคู่บัญชี/ชุดแทนผู้ตรวจ

| ข้อมูลต้นทาง | แนวทางเก็บที่เสนอ | สิ่งที่ยังไม่ทำ / ต้องรับรอง |
|---|---|---|
| 4 แถวที่ขาดเจ้าของ เรื่อง วันที่ และสิทธิ์บางส่วน | เก็บ raw/source ID ในส่วนแยกที่หน้าอ่านปกติไม่เข้าถึง และรวมเลขหลัก/แทรกเดิมในการกระทบยอดกันเลข | ไม่สร้างบัญชีรวม ไม่เติม publish หรือวันที่ปลอม ต้องรับรองวิธีเก็บข้อมูลกันเลขและสิทธิ์ผู้ดูแล |
| 2 แถวที่มีวันหนังสือแต่ไม่มีเวลาสร้าง | เก็บวันเดิม และรักษาเวลาเป็นไม่ทราบ ไม่ใช้ lastupdate แทน | จะนำเข้า history ขั้นต่ำได้หลัง mapping เจ้าของ/ชุด/สิทธิ์ผ่าน และรับรองการแสดงเวลาไม่ทราบ; ไม่ถือว่าปัญหาเวลาได้รับการซ่อมแล้ว |
| 2 แถวยกเลิกที่อ้างชุด 00096/00097 ซึ่งหาย | เก็บ raw/รหัสชุด/ปี/เลข/สถานะเดิมแยก และจดเลขที่ต้องกันภายใต้รหัสชุดเดิม | ยังไม่จับคู่เข้าชุดอื่น ไม่สร้าง prefix แทน ไม่เปิดออกเลขชุดที่ mapping ไม่ผ่าน |
| child 39 แถวที่ parent หาย | เก็บแยกครบพร้อม child ID และ parent ID เดิม ไม่แสดงเป็นผู้รับของหนังสืออื่น | parent ID ไม่ใช่เลขหนังสือ จึงอนุมานชุด/ปี/เลขเพื่อกันเลขเพิ่มจาก child เพียงอย่างเดียวไม่ได้ |

การแยกเก็บต้องรักษาทุกแถว ไม่ทำให้เลขที่มีอยู่ในหนังสือหลักหลุดจากฐานกระทบยอด และไม่เปิดอ่าน metadata ที่ยังกำหนดสิทธิ์ไม่ได้ มี implementation/ซ้อม preservation แล้วตามแนวทางที่ยืนยัน ส่วน importer normalized ยังคงกำหนดให้ mapping ครบ ไม่ข้าม validation และยังไม่ promote ข้อมูลจริงเข้าแอป
