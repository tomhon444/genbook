# T09 — แก้ไขหนังสือและตรวจประวัติ รุ่น local

พัฒนา 13 พฤศจิกายน 2026 (Asia/Bangkok) ตามกฎ T02/T03 โดยใช้บัญชีและ MySQL สังเคราะห์ ไม่มี schema ใหม่ ไม่มี migration หรือ production write

## วิธีใช้งาน

เจ้าของเปิดรายละเอียดจากรายการล่าสุดหรือผลค้นหา T08 แล้วกด “แก้ไขข้อมูล” แก้เรื่อง ผู้รับ หน่วยงานรับเรื่อง ผู้ลงนาม ความลับ และการเผยแพร่ กดบันทึกเพื่อเปลี่ยนข้อมูลพร้อมบันทึกประวัติ PDF ใช้ส่วนแนบไฟล์ T07 เดิม ซึ่งใช้ version เดียวกัน

ในประวัติ เจ้าของดูผู้ดำเนินการด้วยรหัสบุคลากร วันเวลาไทย และ version ได้ กด “ดูค่าก่อนและหลัง” เพื่ออ่านฟิลด์ที่เปลี่ยน การแทน PDF แสดง hash/ขนาด/version ก่อน–หลัง ไม่มีการเผยแพร่ private blob path

ถ้าข้อมูลถูกแก้จากอีกแท็บหรือมีการแนบ PDF หลังเปิดฟอร์ม คำขอ version เก่าคืน 409 ต้องกด “โหลดข้อมูลล่าสุดเพื่อแก้ไข” แล้วเริ่มใหม่ ฟอร์มจับ version ณ เวลาเริ่มแก้ ไม่เปลี่ยน version เงียบ ๆ เมื่อ PDF ในหน้าเดียวกันโหลดรายละเอียดใหม่

เมื่อ server/network ขัดข้องจนยังยืนยันผลไม่ได้ ให้โหลดข้อมูลล่าสุดก่อนลองบันทึกใหม่ ไม่ส่งแก้ซ้ำอัตโนมัติ หากบันทึกสำเร็จแต่โหลดรายการไม่สำเร็จ ยังคงแสดงผลสำเร็จและให้โหลดใหม่

## API และ validation

`PATCH /api/issuance/:id` ต้องมี session และผ่าน same-origin แบบเดียวกับคำขอออกเลข รับ JSON สูงสุด 16,384 ตัวอักษร พร้อมทุกฟิลด์ต่อไปนี้:

| ฟิลด์ | กฎ |
|---|---|
| `version` | จำนวนเต็ม 1–4294967295 ต้องตรงค่าปัจจุบัน (เมื่อเต็มคืน 409 โดยไม่เขียน) |
| `subject` | เรื่อง 1–500 ตัวอักษร |
| `recipient` | ผู้รับหนึ่งคนต่อบรรทัด สูงสุด 20 คน คนละ 200 ตัวอักษร ข้อความรวมสูงสุด 3000 |
| `recipientDepartmentIds` | อาร์เรย์รหัสหน่วยงานภายใน สูงสุด 20 ค่า normalize ไม่ซ้ำและเรียงลำดับ |
| `externalOrganization` | ข้อความหน่วยงานภายนอก สูงสุด 500 ตัวอักษร ต้องเลือกภายในหรือภายนอกอย่างใดอย่างหนึ่ง |
| `signer` | ผู้ลงนาม 1–200 ตัวอักษร |
| `confidential`, `published` | boolean ทั้งคู่ |

ตัดช่องว่างหัวท้ายแบบเดียวกับ T05/T06 ใช้ตัวตรวจข้อมูลเนื้อหาร่วมกัน ปฏิเสธฟิลด์อื่นทั้งหมดแม้ส่งปนกับฟิลด์ที่ถูกต้อง รวม owner/หน่วยงานเจ้าของ/ชุด/prefix/ปี/เลขหลัก/ย่อย/วันที่/เวลาออกจริง/source/request key/hash/PDF pointer/สถานะยกเลิก

400 สำหรับ input ผิด, 401 เมื่อไม่มี session, 403 เมื่อ origin ไม่ผ่าน, 404 สำหรับไม่พบหรือไม่ใช่เจ้าของ, 409 เมื่อ version เก่าหรือเต็ม, 503 เมื่อยังยืนยันผลไม่ได้ Response ใช้ no-store คืนรายละเอียดปัจจุบันพร้อม audit เฉพาะเจ้าของ

## ความถูกต้องและสิทธิ์

- เจ้าของเท่านั้นที่แก้ได้ ไม่ให้ผู้ดูแล/ผู้จัดการชุดเลขหรือผู้อ่านร่วมแก้แทน ไม่ต้องมี grant ออกเลขหรือชุดเลขเปิดอยู่เพื่อแก้หนังสือของตน
- ล็อก owner mutex ก่อนแถวหนังสือ เหมือนการออกเลขและการแนบ PDF ตรวจเจ้าของ/version อีกครั้งภายใต้ lock เปลี่ยนเนื้อหาและเพิ่ม version พร้อม `amended` audit ใน transaction เดียวกัน หาก audit ล้มเหลว rollback ข้อมูลและ version ทั้งคู่
- Audit เก็บ `actor_id`, UTC timestamp, ค่าก่อน/หลังครบฟิลด์เนื้อหา, previousVersion/version หน้า UI แสดงเวลาที่ Asia/Bangkok และเฉพาะค่าที่ต่าง การบันทึกค่าเดิมยังเพิ่ม version และเก็บประวัติว่าไม่มีการเปลี่ยนค่า
- ไม่เปลี่ยนเลขหรือหลักฐานคำขอเดิม `request_key`/`payload_hash` การ retry คำขอออกเลขเดิมยังคืนเลขเดิมพร้อมข้อมูลปัจจุบัน ไม่สร้างเลขหรือ audit ออกเลขใหม่
- เปลี่ยนลับเป็นไม่ลับโดยไม่มี PDF ทำให้ค้างไฟล์ กฎนี้ serialize กับการขอเลขผ่าน owner mutex คำขอปกติ/ย้อนหลังถัดไปถูกบล็อกจนแนบครบ ไม่มีการคืนเลข
- ใช้หน่วยงานรับเรื่องเดิมที่ปิดแล้วต่อได้ แต่เพิ่มหน่วยงานที่ปิดใหม่ไม่ได้ ตรวจหน่วยงานภายใต้ shared lock
- ผู้ที่อ่านหนังสือได้ไม่ได้รับ audit แม้เจ้าของเปลี่ยนจากลับเป็นเผยแพร่ จึงไม่เห็นค่าลับในประวัติก่อนเปลี่ยน กฎอ่าน/ค้นหา/ดาวน์โหลดเดิมใช้สถานะปัจจุบันบน server
- ประวัติ normalized legacy ยังอ่านอย่างเดียว เพราะยังไม่มี version/ประวัติแก้ไขและข้อมูลเนื้อหาครบแบบ issuance การเชื่อมข้อมูลจริงติดตาม T12/T13 ไม่แก้ raw หรือ reservations

- E2E ทั้งระบบ 65/65 (52 regression เดิมและ 13 T09)
- MySQL issuance rules 12/12 รวม concurrency/rollback/retry/วันเวลา/ปี และ production isolation 3/3
- lint/typecheck/build ผ่าน ตรวจภาพมือถือและคีย์บอร์ดแล้ว
- QA อิสระไม่เหลือ finding หลังแก้ validation วันที่ที่ไม่ใช่ string และเพิ่ม malformed-object HTTP regression

ครอบคลุมการแก้ครบฟิลด์และข้อมูลห้ามแก้, คำขอผิดรูปแบบ, สิทธิ์ owner/peer/outsider, ประวัติลับหลังเผยแพร่, concurrent edits/PDF, rollback audit, pending PDF และ owner-lock race, เลขย้อนหลัง, disabled recipients/grants, idempotent issuance replay, สองแท็บ มือถือ คีย์บอร์ด loading/error/reload และการแก้จากผลค้นหา

การเปิดจริงยังต้องผ่าน migration/cutover และบัญชีคณะของ T12/T13 ไม่เพิ่มนโยบายยกเลิกหรือสิทธิ์แก้แทนเจ้าของ
