## ผลนำเข้าและสิทธิ์อ่าน

Preservation → promotion dry-run/rollback → commit/replay ผ่านอีกครั้ง ตรวจ raw 384,725 แถว, reservation 172,131 รายการ, history/details 170,257 รายการ และเก็บแยก 1,874 รายการ โดยไม่เปลี่ยนเลข/เจ้าของ/รายละเอียด/สถานะ PDF เดิม

HTTP ใช้บัญชีจำลองที่ผูก owner/department ของตัวอย่างจริงจากแผน ผลรายละเอียด 9 กรณี:

| ตัวอย่างประวัติจริง | เจ้าของ | บุคลากรหน่วยงานเดียวกัน | บุคลากรนอกหน่วยงาน |
|---|---:|---:|---:|
| ลับ | 200 | 404 | 404 |
| ไม่ลับ ไม่เผยแพร่ | 200 | 200 | 404 |
| ไม่ลับ เผยแพร่ | 200 | 200 | 200 |

ตรวจรายการ history ว่าแต่ละแถวอ่านได้ตามตัวตน และยอดค้นหาตรงกับแผนที่กรองสิทธิ์ครบทุกแถว ไม่กรองหลังแบ่งหน้า ตรวจเลข/เรื่อง/metadata ของรายละเอียดเทียบแผน และ `Cache-Control: no-store` ของ history/detail

ผู้ไม่เข้าสู่ระบบได้ 401 จาก history/search; ตัวอย่างเก็บแยก 3 เหตุผลต่อแต่ละตัวตนได้ 404 และกระทบยอด reservation ที่ไม่มี history ครบ 1,874 รายการ ไม่อ้างว่าทดสอบ HTTP แยกรายการที่เก็บแยกครบทุกแถว App DB user อ่าน raw staging หรือเปลี่ยน gate ไม่ได้

หน้าอ่านประวัติจริงแสดงเลข/เรื่องและสถานะอ่านอย่างเดียวทั้ง desktop/mobile เมื่อเปลี่ยนเป็นตัวตนนอกหน่วยงาน หน้าเดิมปฏิเสธประวัติลับและไม่มีรายละเอียดค้างอยู่ ไม่บันทึก screenshot/video/trace ของข้อมูลจริง

## ผลเดินเลขต่อและคำขอซ้ำ

ใช้ผู้ขอเลขจำลองใหม่ 2 รายที่ไม่มีประวัติค้าง PDF หน่วยงานจำลองใช้รหัส `204` เพื่อใช้ข้อยกเว้นเวลาเดิม ไม่ถือเป็นหลักฐานว่าบุคคลจริงเป็นสมาชิกหน่วยงานนี้หรือได้รับสิทธิ์ชุดเลขแล้ว ไม่ปลด PDF ค้างหรือแก้ประวัติจริงเพื่อให้ทดสอบผ่าน
