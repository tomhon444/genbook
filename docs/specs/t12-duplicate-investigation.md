## แนวทางเสนอสำหรับ normalized history และการเดินเลข

1. คง snapshot/source ID เป็นเอกลักษณ์ประวัติ เก็บเลขดิบและสถานะเดิมทุกแถว ไม่ใช้เลขหนังสือเป็น primary key
2. อ่านแต่ละแถวตามสิทธิ์เจ้าของ ความลับ การเผยแพร่ และหน่วยงาน ห้ามเปิดกลุ่มเลขซ้ำทั้งหมดให้ผู้ใช้เพียงเพราะอ่านได้หนึ่งแถว
3. แสดง source ID และสถานะเดิมเพื่อแยกประวัติเมื่อผู้ใช้นั้นมีสิทธิ์อ่านหลายแถวที่เลขเดียวกัน ไม่เปิดเผยว่ามีแถวซ่อนซึ่งเขาไม่มีสิทธิ์
4. กระทบยอด counter จากทุกเลขที่ต้องกัน รวมรายการยกเลิกและประวัติที่แยกเก็บเพราะข้อมูลไม่ครบ ไม่ลด counter ตามจำนวนแถวหลังคัดแสดงหรือเลือกตัวแทน
5. ให้ผู้รับรองลงผลพิจารณารายกลุ่มก่อนนำข้อมูลจริงเข้าแอป การมีข้อเสนอครบไม่ได้เป็นการรับรองกลุ่มใด
