# T12 — ข้อเสนอ mapping รอบตรวจรับ

สถานะต่อมา: ผู้ใช้ยืนยันข้อเสนอนี้แล้ว ผลซ้อมและคำรับรองจริงอยู่ใน [รายงานหลังรับรอง](t12-confirmed-mapping-rehearsal.md) ข้อความและยอด readiness ด้านล่างคงไว้เป็นหลักฐานข้อเสนอก่อนรับรอง

จัดทำ 20 พฤศจิกายน 2569 (Asia/Bangkok) จาก snapshot ปัจจุบัน SHA-256 `d5f97eb2131c0ba0d7eaee8659f9c9e02f87bf092092385c6dbd4b5181e2d6bb` และ [หลักฐาน CENTRAL วันที่ 19 พฤศจิกายน](t12-central-mapping-evidence.md) SHA-256 `c334440db80eabe3a06eb901129b43e0b83100d9bd5726df29d3a8591bb0cc61`

รอบนี้สร้างข้อเสนอที่ validator เดิมอ่านได้ พร้อมเหตุผลรายรหัส/รายหนังสือและพื้นตัวนับสำหรับตรวจรับ **ยังไม่มีคำรับรอง mapping** ไม่มีการเขียนฐาน นำเข้าประวัติ เพิ่มสิทธิ์ หรือเปิดออกเลข ข้อมูล CENTRAL เป็น MyISAM จึงยังต้องตรวจใหม่ก่อน cutover

รหัสเจ้าของที่จับคู่ได้รวม active 224 และไม่ active 94 รหัส การเก็บประวัติของรหัสที่ไม่ active ไม่ได้เปิดบัญชีหรือให้สิทธิ์ออกเลข เจ้าของที่ไม่มีรหัสและหน่วยงานที่ว่างไม่มีรหัสปลายทางให้สร้างแทน จึงไม่รวมในยอด mapping ด้านบน แต่ยังรวมในการกระทบยอดหนังสือและ reservation

- คงหน่วยงาน ณ วันออกตามต้นฉบับ แม้หน่วยงานปัจจุบันใน CENTRAL ต่างกัน ไม่ย้ายประวัติไปหน่วยงานปัจจุบันอัตโนมัติ
- ชุดเลขที่มี prefix/กติกาปีครบจับคู่แยกกัน 154 ชุด: `00006` ใช้ปีจากวันที่หนังสือ อีก 153 ชุดใช้ปีปฏิทินตาม T01 ไม่รวมชุดที่ prefix คล้ายกัน
- พัก `00047` ซึ่ง prefix/ปีไม่ครบตามกติกาที่รับรองเดิม และพัก `00096`/`00097` ที่ไม่มี reference ต้นทาง ไม่สร้างชุดหรือสิทธิ์แทน
- เสนอเก็บหนังสือเรื่องว่าง 1,860 รายการแยกจากประวัติที่แอปอ่านได้ รักษาข้อความเดิมครบ ไม่เติมชื่อเรื่อง และคงกันเลขเดิมไว้ นี่เป็นข้อเสนอที่ยังต้องรับรอง
- คงเลขซ้ำทุก source ID ไม่ลบ/รวม/เปลี่ยนเลข เก็บวันที่ตามต้นฉบับ และให้ PDF ที่ยังไม่ยืนยันคงสถานะรอ
- สิทธิ์เดิมจาก `bookdept_user` และบทบาทจาก `userbook`/`userlevel` แยกจากการจับคู่เจ้าของ ไม่เพิ่ม grants ในรอบนี้

จำนวนผ่านเงื่อนไขเบื้องต้นไม่ใช่ผลนำเข้า ยังไม่รับรองรายละเอียด/ไฟล์/เวลา/สิทธิ์จริงหรือฐานปลายทาง ทั้ง manifest และ review รายแถวใน mapping ยังเป็น null; policies ยัง pending และตัวตรวจเดิมยังรายงาน 2,389 blockers

## ไฟล์เฉพาะเครื่อง

ชุดข้อเสนอ: `.local/t12/proposal-d5f97eb2-1675f390/`

- `REVIEW.md`: สรุปข้อเสนอสำหรับตัดสินใจ
- `mapping.json`: schema เดิม พร้อม map/hold ที่เสนอ แต่ไม่มีผู้รับรอง
- `decisions.json`: เหตุผลรายรหัส ราย source ID นโยบายที่เสนอ และพื้นตัวนับพร้อม `previewOnly:true`/`approved:false`
- `summary.json`: ยอดรวมและ hash ของหลักฐาน
- `validation.json`: ผล `mappingPlan()` จริง พร้อม blockers และ readiness ที่ปิดอยู่

รหัสบุคคลและข้อมูลราย source ID อยู่เฉพาะไฟล์ Git-ignore ไม่คัดลอกขึ้น issue tracker และไม่เขียนทับ workbench/หลักฐานรอบก่อน

```powershell
node tools/migration/prepare-mapping-proposal.mjs .local/legacy-import/native-d5f97eb2131c/source.sql.gz .local/t12/central-evidence-d5f97eb2-64ae62e7-reviewed
node tools/migration/check-mapping.mjs .local/legacy-import/native-d5f97eb2131c/source.sql.gz .local/t12/proposal-d5f97eb2-1675f390/mapping.json
node --test tools/migration/mapping-proposal.test.mjs tools/migration/prepare-mapping-proposal.test.mjs
```

เครื่องมือสร้างโฟลเดอร์ใหม่ทุกครั้ง ตรวจ hash ของ evidence bytes เทียบ receipt และ snapshot, corroborate reference กับต้นฉบับ และปฏิเสธหลักฐานที่ถูกเปลี่ยน ไม่มีคำสั่งเชื่อม DB, promote, เพิ่ม grants หรือเปิด gate ในเครื่องมือนี้

## การตรวจสอบและงานถัดไป

เทสต์ใหม่ 8/8 ผ่าน: exact/leading-zero IDs, inactive owner, historical department, missing/ambiguous identity, prefix/ปีที่ขาด, ชุด `00006`, source/evidence tampering, เรื่องว่าง/วันที่ผิด, reservation ของรายการพัก/ยกเลิก และ CLI ที่ไม่เขียนทับไฟล์เดิม ไม่แสดงรหัสบุคคล และไม่ยอมรับ receipt hash ผิด Lint/typecheck ผ่าน QA อิสระไม่พบ finding ในขอบเขตข้อเสนอ

ขั้นถัดไปคือให้ผู้ใช้รับรองหรือแก้ข้อเสนอด้านบน โดยเฉพาะวิธีเก็บเรื่องว่างและรายการที่จับคู่ไม่ได้ แล้วจึงบันทึก reviewer/date/evidence จริงและรันตัวตรวจซ้ำ ก่อนซ้อมนำเข้าในฐานแยก ไม่กรอกผู้รับรองแทนผู้ใช้จากคำสั่งให้เตรียมขั้นถัดไป
